SkillPilot · Controlled Claude baseline

Does Claude retain and reuse MCP tool results?

This protocol checks fresh result handoff, same-turn chaining and cross-turn reuse with random signed markers. It establishes a Claude baseline before any real SkillPilot coaching workflow is tested.

Claude custom connector Streamable HTTP MCP OAuth protected Synthetic markers No real learner data

Isolated setup

  1. Use a dedicated adult Claude test account and a blank SkillPilot test learner. Do not bind a production learner.
  2. Use SkillPilot's normal Claude OAuth flow to add the connector under Claude's Customize > Connectors.
  3. Run the isolated server configuration with SKILLPILOT_CLAUDE_COACH_TOOLS_ENABLED=false and SKILLPILOT_CLAUDE_REGRESSION_TOOLS_ENABLED=true.
  4. Open the transparent prompt sheet. It is for the human tester: do not paste the whole file or ask Claude to adopt standing instructions. Copy only the prompt for the current test into a fresh chat.
  5. Enable SkillPilot for that conversation through + > Connectors. Confirm that the connector exposes exactly createRegressionProbe and verifyRegressionProbe. Stop if any coach tool is visible.

What this does not test

  • It does not call a Custom GPT Action or use an OpenAPI Action schema.
  • It does not test learner state, coaching quality or write operations.
  • It does not expose the SkillPilot ID or OAuth credentials to the model.
  • The public REST health check confirms the shared synthetic service only; it does not replace the authenticated MCP run in Claude.

Test matrix

Single Test A prompt Claude reads and openly displays one fresh MCP tool result. One visible createRegressionProbe result
Chain Test B prompt Claude passes all three fields unchanged to the verifier in the same assistant turn. ok=true, proof_valid=true
Cross-turn Test C first prompt, then Test C second prompt The backend objectively validates the exact prior tool result after the user-turn boundary. ok=true, proof_valid=true

Keep all tool activity visible. Do not restart Spring Boot between the two Test C messages. A policy refusal means the measurement did not run; it is not evidence of forgotten data.

How to interpret the baseline

If Single and Chain pass, MCP dispatch and same-turn result handoff work. If Cross-turn also passes in a separate two-message run without the tuple being copied into ordinary assistant prose, the backend attests that Claude reused the complete MCP result across that immediate user-turn boundary. That is the minimum baseline needed before testing the real coach.

A pass is evidence for this controlled conversation and Claude configuration, not a guarantee that arbitrarily old tool results survive context selection or compaction. The coach must still be able to reload current backend state.

After the measured block, restore SKILLPILOT_CLAUDE_COACH_TOOLS_ENABLED=true and SKILLPILOT_CLAUDE_REGRESSION_TOOLS_ENABLED=false, restart Spring Boot, and confirm in a fresh chat that the regression tools are gone.
