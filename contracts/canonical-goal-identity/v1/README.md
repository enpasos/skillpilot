# Bounded canonical goal identity proof, v1

This is a separate repository identity-proof profile. Existing curriculum-package
v1 alias and semantic-body digest rules are unchanged. No runtime alias support,
QA approval, learner-state migration, publication or data application is provided
by generating this artifact.

The fixed migration ID is `canonical-goal-id-format-2026-11-06`. The namespace is
`97d8c00c-411d-5dec-b260-4e6f22ab688b`; the UUIDv5 name is the UTF-8 canonical JSON
array `[migrationId, landscapeId, sourceGoalId]`. Updating the accepted source
commit does not change this tuple or the resulting 164 target UUIDs.

```bash
python scripts/test_canonical_goal_identity_migration.py
python scripts/canonical_goal_identity_migration.py generate \
  --base-commit 212eebd39a28afba212551efd773633fd55d6338 \
  --output docs/dev/ci-graph-repairs/canonical-goal-id-format-2026-11-06.proposal.json
python scripts/canonical_goal_identity_migration.py verify \
  --manifest docs/dev/ci-graph-repairs/canonical-goal-id-format-2026-11-06.proposal.json
```

The example commit is the historical post-weight, pre-ID baseline. An actual
migration requires a **new full proof against the exact commit after separate
semantic repairs**. Unrelated changes to a catalog subject make the old proof
stale, including subjects with no renamed goal. `generate --base-commit` accepts
an exact 40-hex commit; no moving branch name is accepted. Exit 2 means a proposal
was generated or independently reproduced **with blocking hits**. Exit 1 means a
contract failure. Neither is an application approval. A successful proposal has
no undeclared hit or unready active/derived document.

The collision universe contains all 593 runtime-shaped curriculum files outside
`quality`, not just the three changed canonical files. Every source file is bound
by raw SHA256 and landscape owner. All 164 renamed goals have one exact serialized
definition; targets are injective and cannot collide with an existing UUID,
including an equivalent uppercase UUID spelling. Local, exactly qualified and
unique foreign references are resolved explicitly. An unknown explicit owner,
missing endpoint or ambiguous foreign owner fails.

`reference-fields.json` is a closed, versioned declaration of field semantics.
Each active occurrence expands to an exact JSON pointer and before/after endpoint.
Property-key references, such as provenance-registry canonical keys, are distinct
from string-value references. Source IDs inside the corresponding provenance
values remain untouched. No substring replacement is available. The verifier
requires the entire original JSON document after inverse projection, including
array order, descriptions, tasks, thresholds, original timestamps and source
context. Assets and cards are additionally bound as original byte streams.

`canonical-json-profile.json` defines the cross-language semantic hash encoding
and conformance vectors. Numbers use exact decimal values without exponent or
insignificant fractional zeros. Object keys sort by Unicode code point; arrays
retain order. Duplicate properties, nonfinite numbers and unpaired surrogates
are rejected. Raw source/asset/review hashes are separate from canonical semantic
hashes. CLI output names `manifestRawSha256` and `manifestCanonicalSha256`
separately; external acceptance must pin the **raw** digest.

Original review files, source provenance, card bytes and historical authoring
evidence are preserved and classified with explicit reasons. This does not
establish a working QA or learner-state alias consumer. Current derived reports
must be regenerated by their actual producers. Unknown documents/fields and
unready active producers remain blockers rather than becoming accepted history.

A future loader must receive an independently accepted raw manifest digest,
expected source commit and active snapshot identity. It must validate the closed
schema and actual registry/profile/verifier bytes, all bound original and current
catalog/document bytes, the bijection and inverse proof before constructing an
immutable validated capability. `status`, `proof` flags and a self-supplied hash
provide no authority by themselves. Repository and package snapshots require
their own complete source binding; package mode has no repository fallback.

The optional read-only candidate check adds these independently supplied pins:

```bash
python scripts/canonical_goal_identity_migration.py verify \
  --manifest /path/to/accepted-proof.json \
  --expected-base-commit <exact-40-hex-commit> \
  --accepted-manifest-sha256 <accepted-raw-manifest-sha256> \
  --candidate-root /path/to/prepared-tree
```

It checks every catalog source, including unchanged files. A blocked proposal
cannot verify a candidate. There is no `apply`, bypass, timestamp refresh or
baseline exception option.

## Separate source proof A and activation evidence B

The historical `migration.schema.json` and blocked proposals keep their original
meaning. `source-bijection-proof.schema.json` is a separate type that permits only
isolated QA candidate projection. Its producer is:

```bash
python scripts/test_canonical_goal_source_identity_proof.py
python scripts/canonical_goal_source_identity_proof.py generate \
  --base-commit <exact-commit-after-semantic-and-source-producer-repairs> \
  --output docs/dev/ci-graph-repairs/canonical-goal-source-bijection-2026-11-06.proposal.json
python scripts/canonical_goal_source_identity_proof.py verify \
  --manifest docs/dev/ci-graph-repairs/canonical-goal-source-bijection-2026-11-06.proposal.json
```

A reuses the same identity/byte/inverse kernel. It binds all 593 catalog inputs,
the 164 rules, entire source documents and original review/card/asset inputs.
This includes unchanged goal IDs whose prerequisite or containment references
change. The source projection digest is the canonical hash of
`{catalog: catalog.sourceFiles, rules, documents}`. A has six independent artifact
bindings: source schema, field registry, registry schema, canonical JSON profile,
source verifier and shared identity kernel.

The source schema centrally declares eleven exact current-output/identity-proof
paths. Their output bytes and timestamps are absent from A's hashes, so creating
the actual QA reports cannot change its own input proof. There is no general
status-directory exception. Every other unclassified input or unrepaired active
producer is fatal. A does not promote an old blocked proposal, approve an old
review or expose a learner-state/storage operation. Existing QA validators must
still validate authentic original artifacts against the verified original
definition before reporting candidate results.

`activation-receipt.schema.json` separately describes B. It binds A's raw digest,
actual generated outputs with producer/verification receipts, snapshot bindings
and ten explicit state-boundary evidence contracts. This schema is not a B
implementation or an activation receipt. A runtime service must stay closed
until a real B verifier checks those artifacts under independent accepted pins.
No B receipt is generated by the source CLI, and no A capability can construct
a runtime/learner identity service.
