## 2. OpenAI MCP: Authorized Client Binding

!!! info "Binding security architecture for the OpenAI MCP coach"
    Original baseline: 31 July 2026 · Reconciled with the permanent neutral plugin decision of 19 October 2026 (`skillpilot-coach` on `https://mcp-openai.skillpilot.com/mcp`, superseding the earlier `https://mcp-coach-v1.skillpilot.com/mcp` endpoint ahead of directory submission while retaining OAuth issuer `https://skillpilot.com/api/openai/v1`). Identity, cutover, and lifecycle rules are governed by the [Versioning and Lifecycle Plan](../concept/runtime-workflows/openai-plugin-versioning-and-lifecycle.en.md) and the [Stable Origin Runbook](../deploy/openai-stable-origin.md).

<a id="sec-sec-mcp-protection-goal"></a>
### 2.1. Protection Objective

The permanent SkillPilot ID remains the learner-held secret that guards durable learning state. This chapter addresses an orthogonal security objective:

> An unauthorized third-party client must not be able to invoke learner-specific OpenAI V1 MCP APIs, even if it knows both the public server contract and a valid `learningSessionId`.

This boundary leaves the SkillPilot ID as well as learning-goal, mastery, curriculum, and coach semantics unchanged.

<a id="sec-sec-mcp-four-proofs"></a>
### 2.2. Four Independent Proofs

| Proof | Purpose | Binding mechanism |
| --- | --- | --- |
| **SkillPilot Server** | Confidentiality and server authentication | Standard HTTPS/TLS terminated at the dedicated reverse proxy. |
| **OpenAI Connector** | Only hosted ChatGPT connections signed by OpenAI's CA chain reach the production edge | mTLS validated against OpenAI Root CA, Connectors intermediate, `clientAuth` EKU, and exact SAN `mtls.prod.connectors.openai.com`. |
| **Authorized MCP App** | Only the explicitly permitted client receives usable OAuth tokens | Exactly pinned hosted CIMD with `private_key_jwt`; explicitly configured transitional Basic and public desktop CIMD with PKCE `S256` remain distinct profiles without method fallback. |
| **Active Learning Session** | The concrete chat addresses strictly the learner chosen at WebGUI launch | Fresh 24-hour `learningSessionId` minted on every **Lernen starten** / **Start learning** click and required on every domain MCP tool call. |

Every domain MCP call must satisfy cumulatively:

```text
valid client- and resource-bound OAuth access token
AND
valid explicit learningSessionId
AND (in production hosted enforce mode)
valid OpenAI connector client certificate
```

OAuth authenticates and authorizes the App; the learning session selects the learner. Neither proof substitutes for the other.

<a id="sec-sec-mcp-oauth-profile"></a>
### 2.3. Binding OAuth Client Profile

The hosted ChatGPT directory route (**SkillPilot Coach**, technical name `skillpilot-coach`) follows the profile-specific decision of 11 September 2026 together with the neutral endpoint of 19 October. The [OAuth profile runbook](../deploy/oauth-client-authentication.md) distinguishes:

- `chatgpt-cimd-jwt`: an exactly permitted CIMD identity with verified metadata and JWKS; `private_key_jwt` only;
- `chatgpt-basic-transition`: an explicitly intended existing confidential client with a protected secret and `client_secret_basic` only, never a JWT-client fallback;
- `chatgpt-native-cimd-public`: a separate, exactly pinned public desktop profile using `none` with PKCE `S256`, client/loopback callback `7yTcOAOqrumX` under the [Native CIMD Runbook](../deploy/openai-native-cimd.md);
- for every profile, exact client identity and callback allowlist, PKCE `S256`, and the sole Resource/Audience `https://mcp-openai.skillpilot.com/mcp`;
- separate read/write scopes, short access-token lifetime, rotating refresh tokens and revocation.

The implementation in [OpenAiDeOAuthConfiguration.java](https://github.com/enpasos/skillpilot/blob/main/backend/src/main/java/com/skillpilot/backend/openai/de/oauth/OpenAiDeOAuthConfiguration.java) binds the method to the client identity. The [assertion validator](https://github.com/enpasos/skillpilot/blob/main/backend/src/main/java/com/skillpilot/backend/openai/de/oauth/OpenAiDeJwtClientAssertionValidator.java) checks identity, time limits and replay, among other conditions. Profile implementation proves neither activation nor real-host acceptance. Open DCR, unpinned CIMD and arbitrary `none` clients remain excluded.

Only the transitional Basic profile has a shared client secret. It exists exclusively in protected ChatGPT App configuration and the SkillPilot server environment, never in repositories, browser bundles, launch prompts, chats, MCP arguments, responses or logs. Neither JWT nor public desktop clients acquire a Basic fallback.

<a id="sec-sec-mcp-oauth-checks"></a>
### 2.4. OAuth Flow and Resource Validation

The Authorization Server accepts an authorization-code flow only when (1) `client_id` matches an explicitly pinned profile, (2) `redirect_uri` matches its byte-exact allowlist, (3) PKCE `S256` is used, (4) `resource` equals the active MCP resource, and (5) only permitted scopes are requested. At the token endpoint, the JWT profile proves its identity with a valid signed assertion; the transitional Basic client uses only its HTTP Basic secret. The public desktop profile still requires PKCE code binding.

On every MCP request, the Resource Server verifies token signature or active introspection, issuer (`https://skillpilot.com/api/openai/v1`), expiry and revocation, exact audience/resource, exact client ID, required read or write scope, and the explicit valid `learningSessionId`. A valid OAuth token can neither select a learner nor create a session; the OAuth subject is never an identity source or fallback.

<a id="sec-sec-mcp-session-binding"></a>
### 2.5. Learning Session as Separate Application Binding

Per the [OAuth and Learning-Session Contract](../concept/runtime-workflows/openai-mcp-oauth-learner-session-architecture.en.md), clicking **Lernen starten** / **Start learning** mints a fresh random ID on every start (valid for a fixed 24 hours without extension, stored server-side solely as an HMAC hash linked to the learner). New domain operations require at least `PT1H` remaining lifetime (exact `PT1H` is valid). An already committed write may replay its stored result without re-mutating state only when at least `PT1H` remains and tool name, canonical arguments, `clientRequestId`, pinned workflow/curriculum availability, and canonical learner revision all match.

`SESSION_REQUIRED`, `SESSION_RENEWAL_REQUIRED`, and `SESSION_VERSION_UNAVAILABLE` are session boundaries rather than OAuth errors: the coach outputs `instruction` verbatim (or selects the exact localized entry from `instructions`, appending `startUrl` only if absent) without domain output, retry on the expired session, or OAuth re-authentication. The learner starts a fresh session in a new chat from the first-party WebGUI while the permanent SkillPilot ID stays server-side.

<a id="sec-sec-mcp-mtls-edge"></a>
### 2.6. mTLS at the MCP Edge

Hosted ChatGPT connectors present an OpenAI-managed client certificate during TLS handshake. The dedicated MCP virtual host trusts solely the published OpenAI Root CA and Connectors intermediate (without pinning rotating leaf certificates), while a loopback-bound verifier checks certificate chain, `clientAuth` EKU, and exact SAN `mtls.prod.connectors.openai.com`:

- **`observe`:** Valid certificates classify as `VERIFIED`; connections without a certificate pass provisionally to the unchanged OAuth layer and count solely as `OBSERVE_NO_CERT` (for controlled integration and native desktop verification, not a hosted publication state). Any invalid presented certificate is rejected unconditionally.
- **`enforce`:** External `/mcp` calls require `VERIFIED`. Only direct loopback socket peers may exercise the unchanged OAuth path locally as `LOCAL_OPERATOR`; internet headers, query parameters, and `X-Forwarded-For` never create a bypass.

Protected-resource metadata and domain-verification challenges remain reachable without a client certificate. mTLS authenticates OpenAI connector infrastructure and substitutes for neither OAuth nor `learningSessionId`.

<a id="sec-sec-mcp-fail-closed-secrets"></a>
### 2.7. Fail-Closed Startup Invariants and Secret Lifecycle

When the OpenAI V1 provider is enabled, server startup fails closed if any invariant is missing or inconsistent: dedicated high-entropy `SKILLPILOT_SIGNING_SECRET` with at least 32 non-whitespace characters (no placeholders or defaults, never logged), consistent pinned client configuration (exact client ID, profile-bound method and verified JWT metadata/JWKS or a sufficiently strong Basic secret, exact callback allowlist including the authorized native loopback callback, PKCE `S256`, exact HTTPS resource and OAuth endpoints), exact mode agreement across root nginx, backend, and internal classification, and disabled open DCR / unpinned profiles. Port `8787` must remain closed to the public internet; the reverse proxy terminates TLS and forwards only approved routes to `/internal/openai/v1/mcp`.

The production OAuth client secret is generated outside the repository, stored identically only in ChatGPT App settings and the SkillPilot server environment, never echoed in status or error endpoints, and rotated immediately upon suspected compromise (with token revocation and App re-authorization). Rotating `SKILLPILOT_SIGNING_SECRET` intentionally invalidates active learning sessions as a planned session cutover. Rotating OAuth client credentials never preserves or reactivates sessions as an identity substitute.

<a id="sec-sec-mcp-tests-and-assumptions"></a>
### 2.8. Acceptance, Negative Tests, Residual Assumptions, and References

Before release, objective negative tests must fail closed for: token requests missing their profile-required proof, carrying an invalid/replayed JWT assertion or wrong Basic secret, or naming a foreign client ID; unpinned auth methods (`client_secret_post`, open DCR, unpinned `none`/CIMD/`private_key_jwt`); mismatched callback URL or missing/invalid PKCE; missing/wrong resource or scope; revoked/expired tokens; valid OAuth without `learningSessionId` and valid session without OAuth; unknown, tampered, revoked, or expired sessions; direct bypass to port `8787`; and in `enforce` mode any external `/mcp` request lacking a valid OpenAI client certificate, presenting a wrong chain/SAN/EKU, or spoofing forwarding/classification headers. Positive end-to-end verification runs through the configured App (public positive `enforce` mTLS proof can only be executed by the real hosted ChatGPT connector holding OpenAI's private key).

**Residual assumptions:** This architecture does not protect against compromise of the SkillPilot host, reverse proxy, or ChatGPT App configuration, learner-side loss of a SkillPilot ID or live session link, leak of the production client secret, or deliberate sharing of a valid access token paired with a live session — mitigated via secret rotation, short token TTLs, fixed 24h session lifetimes, revocation, minimal scopes, and redacted logging.
