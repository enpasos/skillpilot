## 1. Skill Graph Production Pipeline

This chapter defines the general, repeatable, auditable blueprint for turning any authoritative or institutional curriculum source into a clean `SkillLandscape` JSON graph under `curricula/<...>/json/<file>.json` (or `curricula/DE/Gymnasium/canonical/`; for exam authoring, see [5](exam-example.md#sec-pp-exam-example)).

<a id="sec-pp-sg-outline-json"></a>
### 1.1. Inputs and Steps 0–2: Extraction, Outline, and JSON Generation

Inputs comprise (1) a normalized plain-text source extract capturing topics, outcomes, prerequisites, grading scope, and source URL/locator, (2) a human-curated outline separating root, clusters, and measurable atomic goals, plus optional (3) sibling landscapes for consistent naming and ID patterns:

- **Step 0 (Extract source):** Normalize the official curriculum into clean plain text (no HTML) with an explicit URL/page reference.
- **Step 1 (Structured outline):** Create a root node and subject-matter clusters; cut competencies into measurable **atomic goals** (typically assessable with 1–3 tasks, phrased as "The learner can ..."). Years and phases belong in program/plan structures and learner-facing composition views rather than defining durable canonical goal identity. A declared learning unit needs its applicable own contract; neither a cluster nor an exam folder declares one automatically. Plan motivation anchors and local assessment endpoints according to the applicable route profile; existing E/Q folders are no universal outline requirement for new curricula.
- **Step 2 (Encode JSON):**
  - **Stable IDs:** Project-namespaced UUID v5 or deterministic mapping from `(landscapeId, shortKey)` (`shortKey` is optional, unique within `landscapeId`; repeating the same `(goalId, shortKey)` pair across locale files is valid, reusing one `shortKey` for distinct `goalId`s is forbidden).
  - **Fields and metadata:** The current [Landscape Reference](../dev/landscape-json-field-reference.md) and its schema determine required fields and allowed values. Maintain stable goal identity, text, `requires`, `contains`, and subject-matter classification explicitly. Where retained, `dimensionTags.phase` is compatibility/view metadata; it replaces neither program placement nor a unit contract.
  - **Localization, assets & links:** Multilingual landscapes keep separate meaning-aligned locale JSONs; co-located images use relative Markdown paths. `sourceRef` holds canonical provenance, while `resourceLinks` holds ordered learning links (broad overviews on root/clusters, goal-specific practice/visualization links on atomic nodes).

<a id="sec-pp-sg-relations-qa"></a>
### 1.2. Steps 3–7: Relations, Reference Implementations, Validation, and Registration

- **Step 3 (`contains` hierarchy):** Form an acyclic DAG (cluster $\to$ subgoals) with shallow, meaningful grouping.
- **Step 4 (`requires` sequencing):** Author **atomic-to-atomic** prerequisites without transitive redundancy ([Graph Definition](../concept/skill-graph/graph-definition.md), [Graph Validation Rules](../qa-ci/graph-validation-rules.md)); inherited cluster `requires` remain a transition mechanism only. `requires` denotes necessary preparation, while `examData.coveredGoalIds` claims assessment coverage; neither replaces the other. Support the motivation-to-local-autonomy routes required by the applicable QA profile with genuine subject-matter prerequisites. Repair missing assessments or routes through suitable tasks and curriculum changes, never invented prerequisites. Use the canonical catalog and its current QA reports as active authoring examples; immutable Hessen snapshots under `input/HE/upper-secondary/source-json/` document provenance rather than prescribing a new model.
- **Step 5 (Validation & manual reviews):**

```bash
cd app
npm run validate:graph
```

Complement structural checks with manual atomicity ([Atomic Review](../qa-ci/atomic-review-process.md)) and prerequisite ([Requires Review](../qa-ci/requires-review-process.md)) passes. A structural or route pass does not establish assessment coverage; independently review the task, solution, scoring rubric, and permitted passing combinations. The [unit proposal of 19 November 2026](../concept/skill-graph/unit-assessment-discussion-2026-11-19.de.md) does not yet change existing contracts or QA gates.

- **Step 6 (Register curriculum):** Add root curricula to `curricula/curriculum_manifest.json` or attach sub-curricula via parent `contains`.
- **Step 7 (QA checklist):** Clear, assessable atomic goals, canonical atomic `requires`, acyclic `contains`/`requires`, complete routes required by the applicable QA profile, stable IDs, consistent subject-matter/placement metadata, and aligned localization. Report formal checks, independent content review, and practical trials separately.
