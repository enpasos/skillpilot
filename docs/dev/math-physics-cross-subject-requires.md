## Reference and prerequisite contract

Authored cross-subject edges use existing stable goal IDs. A bare ID resolves
locally first and then to an unambiguous global definition. Existing qualified
references resolve to their specified owner; a miss never silently falls back
to a differently qualified owner. Equivalent repeated definitions can resolve
globally; conflicting repeated definitions must be reconciled or referenced in
their explicit authoring context. Owner paths and definition hashes are retained
for review rather than overwritten by filesystem traversal order.

Effective prerequisites follow recursive direct plus `contains` parent
inheritance, including the existing compatibility self-exclusion at each
inheritance step. They never imply transitive mastery or automatic transitive
reduction. Direct and effective cross-landscape cycles fail graph validation
with goal IDs, files and inherited origins. Local compatibility-copy definition
drift is reported as visible warning debt by the graph gate and remains an
explicit inventory conflict; it does not obtain approval from that warning.
The baseline contains 19 such Mannheim graph-definition warnings.

Runtime readiness checks those declared and inherited prerequisites, rather
than adding every forward-reachable ancestor as another requirement. The current
regression `manualOrImportedDependentMasteryDoesNotCreateTransitiveMasteryOrRequirements`
keeps a target ready when its direct intermediate goal is mastered and that
intermediate's own prerequisite remains unassessed. Adding the deeper goal as a
direct prerequisite blocks the target. Thus a topologically overlapping direct
edge can still be an intentional arithmetic guard; removing it changes behavior
and needs an explicit didactic decision. The uniform-motion candidate retains
its guard while this direct-set minimality question remains pending.

Proposal graph validation uses the same complete reference universe as the
global graph gate, including retained compatibility definitions needed by live
overview references. Those definitions are not added to the active review
selection and cannot become prerequisite nominees through this lookup. Cycles
through them still fail before a new proposal is sealed.

Prerequisite lookup must retain the canonical prerequisite when its subject is
outside current targets, focus, course/year/stage or applicability projection.
Mastery of a dependent never creates or suppresses prerequisite mastery.
Projection roles are explicitly authored `target` or `prerequisiteOnly`; they
are not inferred from a new edge. Standalone package closure and host/runtime
acceptance require their own validation.

## Decision and independent-review records

Author ledgers contain `schemaVersion: 1` and a `decisions` array. Each record
has `decisionId`, `familyId`, `dependentGoalId`, the proposed complete
`prerequisiteGoalIds` set of cross-subject atomic goals, `decision`, an individual
`rationale`, `evidenceKind`, structured `sourceRefs`, `applicability`, `author`
and `reviewInput`. The final set can differ by additions and removals; it is
not merely an additions list.

Decision states are `pending`, `add`, `retain`, `remove`, `replace`,
`no_cross_subject_required`, `granularity_gap`, `scope_gap`, `source_gap`, and
`review_required`. A negative decision still needs an individual explanation.
Unresolved states remain open. Necessity across every dependent scope and
possible alternatives must be addressed explicitly through
`applicability.universality` (`allDependentScopes`, `boundedScopes`, or
`unresolved`), `scopes`, and `alternatives`.

`evidenceKind` distinguishes `didacticSequencing` from `directSourceStatement`.
Source references use repository `path`, `recordId`/`locator`, and `supports`
(`goalSemantics`, `scope`, or `prerequisite`). Mapping a goal to a curriculum
does not prove that the curriculum directly states its prerequisite edge.
Preserve references and concise rationales; do not reproduce source passages.

`reviewInput` separately binds `semanticSha256`, `prerequisitesSha256` (direct
prerequisites, inherited origins and prerequisite semantics) and `scopeSha256` (applicability, relevant
inheritance metadata, provenance and current mapping records). Rebinding hashes
is mechanical work and never a new substantive decision. Independent review is
a separate artifact with `authorLedgerSha256`, `inventorySha256`, and per
`decisionId` records containing reviewer, rationale, `approved`/`rejected`/
`pending`, and the exact reviewed `reviewInput`. The same author cannot satisfy
the separate-review identity check. A technical checker cannot establish the
quality or independence of a purported reviewer by itself.

The current per-goal scope checksum covers that goal's own applicability,
placements, applicability metadata, provenance and mapping records. It does not
bind ancestor applicability/provenance or external composition-view definitions.
Those wider changes still require the separate projection, runtime and M7
checks; the per-goal checksum alone does not establish complete scope acceptance.

Prepare an immutable unreviewed proposal packet with
`npm run prepare:cross-subject-requires-proposal -- --ledger <original-author-candidate> --output <candidate-packet>`.
The current preparer is deliberately scoped to canonical Gymnasium; other
families must resolve ownership and semantic roles first. It computes the exact
proposed graph in memory, preserving internal prerequisites, and records each
decision's baseline and proposed inputs, full before/after `requires` arrays,
change hash, and proposed prerequisite semantic/scope inputs. The independent
record must additionally bind `proposalBindingSha256`. `add` cannot silently
remove edges, `remove` cannot add edges, and `retain` cannot alter them.
`replace` requires at least one addition and one removal. The proposed set is
complete for the foreign subject, including existing cluster edges; internal
subject edges are preserved and new nominated prerequisites must be reviewed
curricular atomic goals. The preparer checks the persisted inventory against a
fresh source build and binds the exact bytes it read. It fails before sealing
invalid actions, unresolved references or global cycles, and refuses every
existing output path, including an unreviewed sealed packet. Validation also
checks that the proposed array matches the complete nominated foreign set,
preserves internal edges, and has current, unambiguous prerequisite definitions.

After adoption, the same reviewed packet remains immutable. Validation accepts
its exact baseline or exact proposed current state; it never refreshes approved
verdicts to new hashes. The review's inventory hash remains the packet's original
`baselineInventorySha256`, while current per-goal and prerequisite bindings prove
the implemented state. Unrelated/current drift that changes those bindings fails.

## Commands and completion gates

Run from `app`:

```bash
npm run report:cross-subject-requires -- --write
npm run check:cross-subject-requires
npm run test:cross-subject-requires
npm run validate:graph
npm run report:cross-subject-requires -- --check \
  --ledger curricula/quality/cross-subject-requires/canonical-gymnasium.author-decisions.json \
  --independent-review curricula/quality/cross-subject-requires/canonical-gymnasium.independent-review.json \
  --family canonical-gymnasium --require-complete
```

The last command requires complete independently accepted canonical coverage;
do not run it as a claim of completion while those artifacts are candidates.
The generated file uses compact JSON. Effective sets resolve through
`effectivePrerequisiteSets[effectiveRequiresRef]`; origin-set indices resolve
through `prerequisiteOriginSets[prerequisiteOriginsRef]` into
`prerequisiteOriginTable`; source file groups resolve through
`sourceBindingFileSets[sourceBindingFilesRef]`. This stores evidence once and
keeps every per-goal fingerprint independently bound.

Completion proceeds in measurable stages: inventory the canonical Gymnasium
Mathematics/Physics scope and deduplicate owners; author individual decisions;
independently review the exact
candidate; apply only accepted atomic edges; regenerate and verify current
bindings, applicability, routes and the protected M7 floors; test persistence,
frontier, prerequisite-only lookup and scoped learning behavior. A stage is
closed only when its complete Gymnasium goal universe has
current reviewed decisions, relevant conflict/gap records are resolved, the
accepted graph matches the decisions, global direct/effective DAG checks pass,
and required runtime and curriculum-quality checks pass. No publication or
deployment is authorized by this workflow.
