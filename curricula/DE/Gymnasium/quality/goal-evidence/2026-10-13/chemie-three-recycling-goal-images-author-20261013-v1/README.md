# Three prospective Chemistry image candidates

Inactive author deliverables for the three complete source-duty goal candidates. The three new PNGs are byte-exact copies of actual built-in `image_gen.imagegen` output. Existing images, active canonical goals, app assets and backend assets were not changed.

Each goal directory contains the actual final prompt, prepared helper metadata, PNG, factual/provenance metadata, actual call trace and an import dry-run. All PNGs are native 1672 × 941, close to 16:9. Inspection copies at 360 and 680 px are recorded in `asset-facts.json` and kept under `tmp/checkpoint-chemie-20261013/recycling-three-images-author-previews`.

`AUTHOR.actual-image-findings.json` records author observations and remaining representational risks. This is not an independent gate-V decision. No scientific source vote, learner-performance evidence, strict-M7 gain, Human Approval or Human Trial is claimed. Separate exact-goal/hash-bound review of the actual PNG bytes remains required.

`example-facts.sources.json` records the narrow primary-source check for the selected examples: platinum catalyst in a PEM fuel cell, aluminium primary/secondary resource and energy comparison, and professional battery/accumulator collection and material recovery. Examples orient the learner; they are not additional normative curriculum duties.

The preparation helper was used with `CANDIDATE.inactive-landscape.json`. The import helper was run only with `--dry-run`: its paths remain hardcoded to canonical source, app and backend asset roots even when the landscape is inactive. Therefore the deliverable uses manually copied inactive PNGs inside this author root and stock-shape proposals in `CANDIDATE.resource-link-proposals.json`. No active import was performed.

Built-in tool mode was used without image-input arguments. The existing primary-cell and iron-route illustrations were inspected for style and described verbally; their bytes were not passed to the generator or copied into the new artwork. The tool exposes no model version, so none is invented. There is one actual attempt per goal and no discarded attempt. Original generator files remain under `/home/enpasos/.codex/generated_images/`.
